# Bug 02 – Payroll Run Stored Zero Totals Despite Salary Structure (Fixed 03-10-25)

## Summary
- **Module:** Payroll > Payroll Calculation
- **Symptom:** Payroll run completed successfully but all payslip totals (gross/net/basic) remained `0.00` and no payslip lines were stored.
- **Environment:** Regression suite (`PayrollRunCalculationTest`) after reintroducing calculation logic.
- **Impact:** Payroll outputs unusable; PDF/email exports would contain empty amounts.

## Root Cause
- When refreshing an existing payslip the service only reset totals to zero but never re-populated payslip lines.
- Calls to `calculatePayslipComponents()` existed only in the manual “recalculate payslip” path.
- The regression test used seeded components with random codes, so helper normalization never recognised them as `BASIC_SALARY` → `basic_salary` field stayed at 0.

## Fix
1. Reintroduced the component generation pipeline inside `calculateEmployeePayroll()` via a reusable `calculateForPayslip()` helper:
   - Deletes previous lines, rebuilds them from `SalaryStructureComponent`s.
   - Updates totals and stores `basic_salary` when `BASIC_SALARY` exists.
   - Handles fixed, formula, and variable components.
2. Added debug logging around component evaluation and hardened error handling.
3. Updated `PayrollRunCalculationTest`:
   - Uses canonical component codes (`BASIC_SALARY`, `INCOME_TAX`).
   - Asserts employees processed, run totals, payslip totals, and individual component amounts.

## Validation
- `php artisan test --filter=PayrollRunCalculationTest`

## Notes
- Keep component codes uppercase to match helper normalization.
- Additional coverage for variable-net components pending future tasks.
